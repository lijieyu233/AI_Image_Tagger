# 体验改进方案：让分类不再是黑箱

> 针对三个反馈：① 排版/操作逻辑不人性化；② 分类模型没有任何设置、完全看不明白；③「最早有接入 API 的功能」找不到。
> 原则对齐初始设计（docs/00-方案总览.md）：**自动标只是建议、标签受控、主路径离线、VLM 只当难例加料且默认关。**

---

## 〇、先回答：API 接入功能去哪了

**它从来只在设计里，代码从未实现过。**

- 初始设计文档（docs/02-技术落地.md）规划了「难例可选走 Qwen-VL（百炼），复用 DASHSCOPE_API_KEY，只许从词表里勾，证件/发票默认不送，没 key 照样能用」。
- 全部历史代码（初始提交 3a72ed9 至今）的 server.js / config.js / 前端里都没有任何 VLM/API 打标实现；唯一痕迹是数据库 `photo_tags.source` 预留了 `vlm` 枚举值。
- 所以不是功能丢了，是没做过。本方案第 E 节把它补上。

## 一、诊断：黑箱感的三个断层

以「不懂原理的普通用户」视角走一遍现在的流程：

| 阶段 | 用户看到的 | 断层 |
|---|---|---|
| 点「✨ 启动分类」前 | 一个按钮，无任何说明 | 不知道它会做什么：按什么分？能分出哪些标签？要多久？**图片会不会被上传？** |
| 分类完成 | toast「打标完成：处理 97 张，标签 193」 | 不知道**分得对不对**：标签直接落在图上，看不出哪些是模型有把握的、哪些是猜的 |
| 发现分错 | 要点开大图→找到标签→点 × | 纠正成本高，且纠正后**没有任何"以后会更准"的感知**（其实后端已经在记录驳回并抬高阈值，但用户完全无感） |

排版层面的放大因素：
- 工具栏 9 个按钮平铺无主次：导入/分类是主路径，导出/批量操作是低频路径，权重相同。
- 侧栏「智能相册」命名抽象：「待确认」「可能证件」对新用户毫无含义。
- 设置页把裸数字「分类阈值 0.25」直接怼给用户——不懂原理的人无从判断 0.25 意味着什么。
- 词表页是工程师视角的 38 行裸表格。

## 二、改进设计

### A. 把「分类」变成有头有尾的向导（P0，消黑箱的主力）

点「✨ 开始分类」不再直接开跑，先弹向导：

```
┌─ 开始分类 ──────────────────────────────┐
│ 分哪些？   ● 新图片（46 张）  ○ 全部重新分  ○ 只分待确认 24 张 │
│                                                           │
│ 怎么分？   ┌────────────┐   ┌────────────────┐          │
│            │ ⚡ 本地快速（推荐）│   │ 🧠 AI 增强（可选） │          │
│            │ 秒级 · 离线     │   │ 更准 · 需配置 Key  │          │
│            │ 图片不离开电脑  │   │ 选中图会上传云端    │          │
│            └────────────┘   └────────────────┘          │
│                                                           │
│ 预计：将打上 2~4 个标签/张，没把握的进「待确认」等你把关        │
│                                    [取消]  [开始 →]        │
└───────────────────────────────────────────────────────────┘
```

跑完不只是一条 toast，出**分类报告**（进度视图就地变身）：

```
✅ 分类完成 · 97 张 · 用时 11 秒
   打上 193 个标签 · 24 张没把握，等你确认 → [现在看] [稍后]
   [再来一次] [返回图库]
```

- 技术上全部复用现有能力：范围即现有的 tagAll 查询条件；报告数据即 job stats（已实现）。
- 「预计 2~4 个标签/张」这句话就是决策层的真实行为（每图上限 4），直接写进文案。

### B. 模型设置：从"参数"到"选项"（P0）

设置页新增「分类方式」区块，替换裸阈值输入：

1. **三档选择**（宽松/标准/严格）保留，每档配一句话人话解释，下方实时预估（复用 `/v1/tag-preview`）：「97 张里约 88 张会被打上标签，其余进待确认」。
2. **「模型能打哪些标签」= 词表分组开关**。每组一个 toggle（关闭"活动"组 → 模型永远不再自动打该组），组内标签可展开看提示句。用户不需要理解阈值，只需要决定"要不要这类"。后端打分时跳过关闭的组即可（配置写 tags.json，`disabled: true`）。
3. **「会联网吗」明确一行**：⚡ 本地模型，图片不离开电脑。开启 🧠 AI 增强时例外（见 E）。
4. **来源可见**：网格/灯箱的每张图显示角标 ⚡（本地）或 🧠（云端 VLM），点开大图标签芯片本就带来源与分数（已实现）。

### C. 让"分得对不对"可判断、可纠正、有回响（P0~P1）

1. **网格快捷反馈**：hover 缩略图出现 👍/👎；批量选中后工具条出现「这些标签不对」。👎 展开该图标签让用户勾掉错的——等价于一键驳回。
2. **「待确认」审阅流（刷题式）**：点侧栏「待确认」→ 主区域变成大图审阅模式：左大图 + 右侧建议标签 + 两个大按钮 [✓ 对] [✗ 不对]，键盘 ←→ 翻图、1=对、2=不对。把 review 从"一个筛选器"升级为"一个工作流"。数据层零新增（驳回已落 feedback 表并影响阈值）。
3. **回响**：每次驳回后 toast 一句「已记住：以后"医院"这类会更严格」（后端 reject 阈值 +0.008/次 已存在，只差说出来）；待确认清零时给完成提示。

### D. 排版重排（P1）

- **工具栏分级**：常驻只留 [🔍 搜索] [📂 导入] [✨ 开始分类（主按钮）]；[导出] 移入「···」更多菜单；导出/加标签/删除只在选中图片后浮现（批量条已有，保留）。
- **侧栏三段**（窄、像文件管理器，符合原设计稿）：
  - 相册（说人话）：全部 · 新导入 · 还没分类 · **模型没把握（24）** · 疑似重复 · 证件/发票
  - 高频标签（保留前 6）
  - 底部：「分类设置」（带 ⚡/🧠 当前方式指示灯）
- **空状态引导**：无图时主区域显示三步图示：① 导入 → ② 开始分类 → ③ 没把握的你来拍板。一键直达第①步。
- **词表页改卡片**：分组卡片 + 组开关 + 组内标签 chips + 顶部搜索，替代裸表格（数据结构不变）。

### E. 补上 API 接入：AI 增强打标，默认关（P2，需要 Key 联调）

严格按原设计做"难例加料"，不做全量上传：

1. **设置页「AI 增强（可选）」**：Provider 选择（阿里百炼 Qwen-VL / OpenAI 兼容接口）、API Key 输入（掩码存储，存 `data/settings.json`，不入库不进 git）、总开关。
2. **只送难例**：仅「待确认」相册 + 用户在向导里显式选了 🧠 的批次。送图前显示「本次将上传 N 张」。
3. **输出受控**：要求模型只从词表选标签、输出 JSON；禁词扫描；置信度记 1.0、`source='vlm'` 落库；界面角标 🧠。
4. **隐私红线**：「文档/证件」组默认不送云端（原设计明确红线），组开关里可显式放开。
5. **无 Key 时主路径完全不受影响**（原设计："没 key 照样能用"）。
6. 后端新增 `backend/src/vlm.js` + `POST /v1/tag-vlm`（复用 job 轮询机制），灯箱可对单图「用 AI 增强重新分类」。

## 三、分期与验收

| 期 | 内容 | 验收 |
|---|---|---|
| P0 | 分类向导 + 分类报告 + 设置页「分类方式」（三档/组开关/联网说明）+ 网格快捷反馈 | 不懂原理的用户不看文档能说出"它会本地打标、分错的能一键纠正" |
| P1 | 待确认审阅流 + 工具栏分级 + 空状态引导 + 词表卡片化 + 来源角标 | 待确认 24 张能在 1 分钟内清完；主工具栏 ≤3 个常驻按钮 |
| P2 | VLM API 接入（默认关） | 无 Key 行为不变；有 Key 时待确认图片可选送云端并带 🧠 角标；证件组默认不上传 |

> 风险提示：P0/P1 全部是前端交互重组 + 少量配置字段（组开关/人话命名），数据层几乎不动；P2 涉及外部 API 联调与 Key 管理，需要你提供百炼或 OpenAI 兼容的 Key 才能真正跑通。
