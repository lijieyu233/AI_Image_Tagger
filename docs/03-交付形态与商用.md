# 交付形态与商用

## 1. 先卖给自己，再卖给谁

个人相册只是狗粮。能收费的是同一套内核：

| 客户 | 痛 | 我们给 | 不给 |
|---|---|---|---|
| 你自己 | 手机几万张找不到 | 本地库 + 词表 + 查看器 | 云、手机 App |
| 设计/摄影工作室 | Eagle 贵、中文场景弱 | 词表可定制、按项目分库、导出选图 | 在线协同 |
| 学校宣传/档案 | 活动照片堆积、不能上公有云 | 内网一台机、标签=活动/年级/场地 | 人脸实名默认关 |
| 医院宣教/环境照 | 合规，图不能出网 | 纯离线 CLIP，VLM 可关 | 病历影像（那是 PACS，别碰） |

心理健康项目的视觉服务是「评测人脸」，这套是「相册资产」。**代码和词表分开，不要接到评测引擎上**，避免合规口径串了。

## 2. 包装成三个 SKU

| SKU | 含什么 | 价怎么定 |
|---|---|---|
| 个人版 | 单库、CLIP、查看器、adb 脚本 | 自用 / 低价买断 |
| 专业版 | 多库、自定义词表、导出工单、可选 VLM 难例 | 工作室年费 |
| 内网版 | 离线权重包、关所有出网、安装与培训 | 学校/单位项目价 |

第一期只把个人版做硬。专业/内网是表结构已经预留（`library` 概念、yaml 词表、VLM 开关），不是另起炉灶。

## 3. 成本（讲得清才是产品）

- 推理：本地 CLIP，电费级。无按张账单。
- 可选 VLM：按难例，百张以内几毛到几块，默认关。
- 存储：原图仍在用户盘；软件只加约 5～15% 的缩略图。
- 硬件：CPU 能做；有 NVIDIA 更爽。不绑服务器。

对比「全扔百度看图」：万张图以后账单和隐私都过不了单位采购。

## 4. 风险

| 风险 | 处理 |
|---|---|
| 模型把证件内容看太清还外传 | 文档类默认不走云；库目录本机 |
| 绿盾加密导致缩略图「损坏」 | 写盘用受信进程；发布前 node 扫文件头 |
| HEIC 一堆黑图 | 第一期就把 pillow-heif 当必装，写进安装检查 |
| 用户以为会自动删手机重复 | 软件不碰手机删除；导出「待删」清单，人自己清 |
| 人脸误识惹事 | 默认关；开了只给「脸 1、脸 2」，人命名 |

## 5. 建议的落地顺序

1. 你先把手机里**最近一年**拷到 `inbox`（先别全量，验证词表）
2. 落地导入 + CLIP + 查看器（[[02-技术落地]]）
3. 你用一周改词表（哪些标根本不会点，删；缺的补）
4. 再全量历史照片
5. 词表稳定后再谈安装包 / 给工作室

词表没被你自己骂过一轮，不要做安装包，更不要对外演示「AI 全能分类」。
